### Ansible docs (ansible-doc)

#### copy

- for copying files from local (master) machine to target machine
    - source can be also remote machine

- OPTIONS
    - content: useful for one-liners instead of giving source file
    - dest: mandatory. 'src' and 'dest' must be same type: file or dir
    - src: local path to source file
        - path can be relative or absolute
    - owner: specify chown like owner of the dest object
    - group: works like owner
    - mode: what is desired permissions of dest file. use 'nnnn' format
        - hox: `stat` file shows symbolic and octal values

#### apt

- manages apt packages

- OPTIONS
    - name: name of package
        - can give multiple
    - state: present for installing, absent for de-install and latest for living in the edge
    - update_cache: updates apt cache before install operation.
        - default is not to update cache

#### file

- for file manipulation in target/slave machine
    - path: mandatory, file or another object under the scope
    - recurse: if true, then set permissions etc. recursive from the path
    - src: when creating (sym)links. what's is source
    - state: absent - deletes the object what is specified in path
    - owner/group/mode: see in copy.

#### user

- for managing user account and attributes

- OPTIONS
    - name: who we are manipulating?
    - create_home: is user deserving home directory
    - comment: Comment section from passwd file, usually the user name.
    - groups: list of groups where user belongs
    - shell: User login shell
    - state: should account exists or not?
    - system: instead of normal user account, create system account
        - not affecting to existing users!

#### authorized_key

- for manipulating SSH keys for user accounts

- OPTIONS
    - user: who is under the scope
    - key: public key
        - string, URL or file

- name: Create group sudoless

- name: Create user antero
  ansible.builtin.user:
    name: antero

## d

Let's implement multi-line file to `/tmp/REMINDER.txt` and let's give fancy permissions to it. I think we can use existing role _host_config_ for that:

```yaml
- name: Create REMINDER.txt file in /tmp
  ansible.builtin.copy:
    content: "Rule one: don't screw up\nRule two: always check twice\nRule three: never forget rule one\n"
    dest: /tmp/REMINDER.txt

- name: modify REMINDER.txt file permissions and ownership
  ansible.builtin.file:
    path: /tmp/REMINDER.txt
    owner: root
    group: sudoless
    mode: '0666'  # -rw-rw-rw- everyone can read and write!
  become: true  
```

Note: using **\n** for newlines, and need `become: true` for setting the owner. Then, let's check:

## e (template)

Use case: I need manipulate target hosts (slaves) `/etc/hosts` file. There's was incorrect hostname due to cloning slaves from master image. 

Solution: Ansible have jinja2 templating language, which is handy to use with build-in ansible variables.

In role _host_config_ I have task:

```yaml
- name: Update /etc/hosts from template
  ansible.builtin.template:
    src: hosts.j2
    dest: /etc/hosts
    owner: root
    group: root
    mode: '0644'
  become: true
```

Template files goes to `./templates` directory. There is a `hosts.j2` file:
```jinja
127.0.0.1	localhost
127.0.1.1	{{ inventory_hostname }}

# The following lines are desirable for IPv6 capable hosts
::1     localhost ip6-localhost ip6-loopback
ff02::1 ip6-allnodes
ff02::2 ip6-allrouters
```
`{{ inventory_hostname }}` is replaced with Ansible build-in variable which is self-explaining inventory hostname of system what is in the loop currently. After running `site.yml` playbook let's check:
